# shadow-ai-scan

リポジトリを 1 つスキャンし、AI サービスを呼び出している行をすべて洗い出して、リスク等級と担当部署を付けて返します。

Python ファイル 1 つだけ、標準ライブラリのみ。インストール不要、ネットワーク接続なし、送信するものは何もありません。

**インターフェースは 6 言語**：日本語、繁體中文、English、한국어、简体中文、Deutsch。

他の言語：[繁體中文](README.md) · [English](README.en.md) ·
[한국어](README.ko.md) · [简体中文](README.zh-CN.md) · [Deutsch](README.de.md)

---

## 30 秒で始める（Python がすでにある場合）

ファイルは 1 つだけです。`shadow_ai_scan.py` を開き、右上の **Raw** から保存してください。置き場所はどこでも、デスクトップで構いません。リポジトリごと clone しても同じです。

ターミナルを開いて実行します。

```bash
# macOS / Linux
python3 shadow_ai_scan.py /path/to/your/repo

# Windows（`py` が使えない場合は `python`）
py shadow_ai_scan.py C:\path\to\your\repo
```

**リポジトリのパスが分からないときは**、そのフォルダをターミナルの窓にドラッグすると、パスが自動で入力されます。

急ぎの等級だけを見る場合：

```bash
python3 shadow_ai_scan.py /path/to/your/repo --level high
```

以下の例はすべて `python3` と書きます。Windows では `py` に読み替えてください。

## Python がまだない場合

Python 本体以外に入れるものはありません。パッケージ不要、ネットワーク接続なし。

| OS | どこで打つか | まず確認 | なければ |
|---|---|---|---|
| Windows | スタートを右クリック →「ターミナル」または「PowerShell」 | `py --version` | [python.org](https://www.python.org/downloads/) から入手。インストール時に Add python.exe to PATH に**チェック** |
| macOS | Command + スペースで「ターミナル」を検索 | `python3 --version` | `brew install python`、または python.org |
| Linux | 普段のターミナル | `python3 --version` | たいてい入っています。なければ `sudo apt install python3` など |

バージョンは 3.9 以上（2021 年以降のものなら大丈夫です）。

**よくつまずく 3 点**

- Windows で `python` と打つと Microsoft Store が開く：`py` を使うか、PATH にチェックを入れて入れ直してください。
- macOS で `python` が見つからないと言われる：macOS には `python3` しかありません。異常ではありません。
- 旧「コマンドプロンプト」で文字化けする：先に `chcp 65001` を実行するか、Windows ターミナルを使ってください。

⚠ 出力には鍵の断片が含まれます。スクリーンショットや貼り付けの前に一度確認してください。

## 何を探すのか

手がかりは 3 つ。機械は嘘をつきませんし、動いたものは必ず痕跡を残します。

1. **コード** — `from openai import OpenAI`、`import anthropic` のような公式 SDK の読み込み。
2. **設定ファイル** — `api.openai.com` のような API ドメイン。コードはいくらでも深く包めますが、通信の出口は残ります。
3. **鍵** — 各社の鍵には決まった接頭辞があります。`sk-ant-api03-`、`sk-proj-`、`AIza`。

---

## 3 段階に分ける理由は、動く人が違うから

件数が何件でも、すべてが同じ重さに見えるなら、どれも重要ではなくなります。そこで各件に等級と担当を付けています。

| 等級 | 内容 | 担当 | 緊急度 |
|---|---|---|---|
| 高 | 鍵がコードや設定ファイルに書かれている | セキュリティ | 今日中に差し替え。議論の余地なし |
| 中 | コードが確実に社外の AI へデータを送っている | 法務・調達 | 契約はあるか。何を送っているか |
| 低 | パッケージが入っている、または痕跡はあるが動いていない | エンジニアリング責任者 | 急がないが、誰かに確認が必要 |

各件にファイル名、行番号、該当行、そして「これが何を意味するか」の一文が付きます。そのまま割り振れます。

## 適用範囲：実際にどの言語を見ているか

**拡張子のホワイトリストがすべてを決めます。** この一覧にないファイルは**開かれもしません**：

`.py` `.js` `.ts` `.tsx` `.go` `.rb` `.java` `.cs` `.php` `.rs` `.kt` `.kts` `.swift` `.yaml` `.yml` `.json` `.toml` `.ini` `.env` `.txt` `.example`

C/C++、Scala、Elixir、`.xml`（`pom.xml` を含む）、Dockerfile、シェルスクリプトは対象外です。
そこに鍵が直接書かれていても、このツールには見えません。

ホワイトリストの中でも、3 つの手がかりの守備範囲は同じではありません。

| 手がかり | 範囲 |
|---|---|
| 鍵のパターン | **言語に依存しません**。対象拡張子のファイルすべて。ただし接頭辞は 4 種類のみ（Anthropic、OpenAI の新旧、Google） |
| AI ドメイン | **言語に依存しません**。7 ドメイン |
| SDK の読み込み | 5 つのキーワード、**大文字小文字は区別しません**：`import` / `from` / `require` / `using` / `use`。Python、JS／TS、Go、Ruby、Java、Kotlin、Swift（`import`）、C#／VB.NET（`using`）、Rust と PHP（`use`）をカバー |
| 依存リスト | 5 種類のみ：`requirements.txt`, `package.json`, `pyproject.toml`, `go.mod`, `Gemfile`。`pom.xml`、`build.gradle`、`composer.json`、`.csproj`、`Cargo.toml` は依存リストとしては読みません。`.kts` は読みますが、Gradle の `implementation(...)` は import ではないため検出できません |

読み込み行では、ベンダー名を**部分一致**で見ます。そのため Rust の `async_openai`、Swift の
`OpenAIKit`、C# の `Anthropic.SDK` も拾えます。この緩和は読み込み行だけで、他は単語単位のままです。

あと 2 点。2 MB を超えるファイルは飛ばします。`.git`、`node_modules`、`__pycache__`、`.venv`、
`venv`、`dist`、`build` には入りません。

さらに広げるのは簡単です。ファイル冒頭のあの数本のリストが設定のすべてで、書き換えてもらうためにそこに置いてあります。

## このツールに見えないもの

これはキーワード照合であり、深い静的解析ではありません。フル実行のたびに、次の 4 点を自分で出力します。

1. **自前でラップされた AI 呼び出し。** コードには `from vendor.llm_client import ask` としか書かれておらず、その下のサービスは見えません。
2. **実行時に決まるパッケージ名。** 環境変数や設定ファイルから来る場合、import 行に照合できる文字列がありません。
3. **行末コメントや複数行文字列の中のコメント。** 行頭しか見ないため誤判定します。
4. **入っている＝使っている、ではありません。** 依存リストは導入の証拠にしかなりません。

N 件見つかったとして、実際にはもっと多いかもしれません。**この一覧は調査の出発点であり、全部ではありません。**

1 と 2 は手抜きではなく、この手法の境界です。見通すにはファイルをまたぐデータフロー解析が必要で、それはもう午後いっぱいで書けるツールではありません。

## CI に組み込む

「高」が 1 件でもあれば終了コード 1、なければ 0。引数の誤りやパス不在は 2 です。

```bash
python3 shadow_ai_scan.py . --level high || echo "鍵の流出あり。このコミットは通さない"
```

今日きれいにしても 3 か月後にはまた生えてきます。CI に入れるほうが、四半期ごとの棚卸しよりずっと安上がりです。

## 言語の切り替え

```bash
python3 shadow_ai_scan.py . --lang ja          # ja / ko / en / de / zh-TW / zh-CN
SHADOW_AI_LANG=ko python3 shadow_ai_scan.py .  # 環境変数でも指定できます
```

指定がなければ OS のロケールに従い、判別できなければ英語になります。

`--level` は 6 言語どの表記でも受け付けます。`--level high`、`--level 高リスク`、`--level 높은 위험` すべて動きます。

## このツールの出どころ

ある回の動画の付属ツールです。その回のテーマは、社内にいったい何件の登録されていない AI 呼び出しがあるのか、そしてなぜ「禁止」の通達では止まらないのか。

このツールは意図的に、リポジトリ 1 つを見て終わります。対象が 200 リポジトリで、定期実行が要り、監査に耐える記録が要り、誤検知が二度と戻ってこないようにしたいなら、それは別の階層の問題です。そのために **ForgeHelm** を作りました。

まずはこの 1 つをスキャンしてみてください。多くの人が最初に気づくことは同じです。数が合わない、という一点です。
