# shadow-ai-scan

あなたの会社には、AI を呼び出している場所がいくつありますか。数字が頭に浮かびましたか——覚えておいてください。

このツールはリポジトリを 1 つ端から端まで読み、AI を使っている行をすべて並べ、それがどれくらい急ぎで、
誰に渡すべきかを教えます。初めて走らせた人の反応で一番多いのは「数字が合わない」です。

Python ファイル 1 つだけ。インストール不要、ネットワーク接続なし、何も外に送りません。インターフェースは 6 言語。

他の言語：[繁體中文](README.md) · [English](README.en.md) · [한국어](README.ko.md) ·
[简体中文](README.zh-CN.md) · [Deutsch](README.de.md)

---

## まず 1 回、30 秒

1. 上の `shadow_ai_scan.py` を開き、右上の **Raw** を押して保存します。デスクトップで構いません。
2. ターミナルを開きます（Windows は「ターミナル」か「PowerShell」、Mac は「ターミナル」）。
3. この 1 行を打ちます。末尾は自分のリポジトリのパスに：

```bash
python3 shadow_ai_scan.py /path/to/your/repo      # macOS / Linux
py shadow_ai_scan.py C:\path\to\your\repo         # Windows（py が駄目なら python）
```

パスが分からない？そのフォルダを**ターミナルの窓にドラッグ**すれば、勝手に入力されます。

Python がまだない？下の〈Python がまだない場合〉へ。

## 何が返ってくるか

一覧です。各件にファイル、行番号、その行の中身、そして「これが何を意味するか」の一文。
一覧は 3 段階に分かれます。見た目のためではなく、動く人が 3 種類いるからです。

**高：鍵がコードに書かれている。** ファイルを開いた人が全員、鍵を手にします。今日中に差し替え、議論の余地なし。
**セキュリティ**へ。

**中：コードが確実に社外の AI へデータを送っている。** 悪いとは限りませんが、3 つ聞くべきことがあります。
その AI 企業と契約はあるか、法務はデータ処理条項を読んだか、送っている中に顧客の個人情報はないか。
**法務と調達**へ。

**低：パッケージが入っている、またはコードに痕跡はあるが動いていない。** 急ぎではありませんが、誰かに聞く必要があります。
誰が入れたか、何のためか、まだ使っているか。**エンジニアリング責任者**へ。

急ぎの等級だけ先に見るなら：

```bash
python3 shadow_ai_scan.py /path/to/your/repo --level high
```

## どうやって見つけるか

人に聞くのではありません。アンケートでは出てきません——エンジニアは自分の「AI」の定義で答え、
彼の目にはそれはただのコーディングだからです。見るのは機械が残した痕跡、3 か所：

1. **コードの読み込み。** AI サービスを使えば、コードは必ずそのパッケージを読み込みます。たとえば `from openai import OpenAI`。隠せません。
2. **設定ファイルの URL。** コードはいくらでも深く包めますが、通信には出口が要ります。`api.openai.com` のような URL は設定ファイルに残ります。
3. **鍵そのもの。** 各社の鍵には決まった接頭辞があります。OpenAI は `sk-proj-`、Anthropic は `sk-ant-`、Google は `AIza`。
   こういう文字列があれば、誰かが使っていて、しかも使い方に問題があります。

3 つ合わせれば、冒頭の問いに答えられます。

## このツールに見えないもの

はっきり言います。これはキーワード照合であって、深い解析ではありません。フル実行のたびに、見えない 4 点を最後に自分で出力します。

1. **自前でラップされた AI 呼び出し。** コードには `from vendor.llm_client import ask` としかなく、下がどのサービスかは見えません。
   たとえば 2 年前に誰かが社内モジュールを書き、その人は辞め、今は誰もどこに繋がるか覚えていない。
2. **実行時に決まるパッケージ名。** 環境変数や設定から来る場合、import 行に照合するものがありません。
3. **行末コメント、複数行文字列の中のコメント。** 行頭しか見ないので誤判定します。
4. **入っている＝使っている、ではない。** 依存リストは導入の証拠にしかなりません。

だから 10 件見つかっても、実際はもっとあるかもしれません。**この一覧は調査の出発点であり、全部ではありません。**
リポジトリに `vendor/` や `internal/` があれば、そこは人が開いて見る場所です。

最初の 2 点は手抜きではありません。見通すにはファイルをまたぐデータフロー解析が要り、それは午後いっぱいで書けるツールではなくなります。

## Python がまだない場合

Python 本体だけ。パッケージは不要です。

| あなたの OS | どこで打つか | まず確認 | なければ |
|---|---|---|---|
| Windows | スタートを右クリック →「ターミナル」または「PowerShell」 | `py --version` | [python.org](https://www.python.org/downloads/) から入手。インストール時に Add python.exe to PATH に**チェック** |
| macOS | Command + スペースで「ターミナル」を検索 | `python3 --version` | `brew install python`、または python.org |
| Linux | 普段のターミナル | `python3 --version` | たいてい入っています。なければ `sudo apt install python3` |

3.9 以上、2021 年以降のものなら大丈夫です。

よくつまずく 3 点：

- Windows で `python` と打つと Microsoft Store が開く？`py` にしてください。駄目なら Python を入れ直し、今度は PATH にチェック。
- Mac で `python` が見つからない？Mac には `python3` しかありません。正常です。
- 文字化けする？旧「コマンドプロンプト」を使っています。先に `chcp 65001` を打つか、Windows ターミナルを使ってください。

⚠ 出力には鍵の断片が含まれます。スクリーンショットや貼り付けの前に、一度見てください。

## もう少し

**言語を切り替える**：繁體中文、English、日本語、한국어、简体中文、Deutsch。指定しなければ OS に従い、判別できなければ英語です。

```bash
python3 shadow_ai_scan.py . --lang ja          # ja / ko / en / de / zh-TW / zh-CN
SHADOW_AI_LANG=ko python3 shadow_ai_scan.py .  # 環境変数でも可
```

`--level` は 6 言語どの表記でも同じです：`--level high`、`--level 高`、`--level 높은 위험`。

**CI に組み込む**：今日きれいにしても 3 か月後にはまた生えてきます。CI に入れれば、AI 呼び出しを足した人のコミットはその場で通りません——
四半期ごとの棚卸しよりずっと安い。「高」があれば終了コード 1、なければ 0。引数の誤りやパス不在は 2。

```bash
python3 shadow_ai_scan.py . --level high || echo "鍵の流出あり。このコミットは通さない"
```

**書き換える**：ファイル冒頭のリストが設定のすべてです。AI 企業を 1 社、ドメインを 1 つ、拡張子を 1 つ足したければ、書き足すだけ。
書き換えてもらうためにそこに置いてあります。

## どのファイルを開くか（範囲を確認したい人向け）

**拡張子かファイル名で決まります。下にないファイルは開かれもしません。**

- コード：`.py` `.ipynb` `.js` `.ts` `.tsx` `.go` `.rb` `.java` `.cs` `.vb` `.php` `.rs` `.kt` `.kts` `.swift` `.scala` `.dart` `.c` `.cc` `.cpp` `.h` `.hpp` `.sh` `.ps1`
- 設定ファイル：`.yaml` `.yml` `.json` `.toml` `.ini` `.txt` `.config` `.xml` `.properties` `.gradle` `.tf` `.tfvars` `.env`／`.env.*`（`.env.local`、`.env.production` を含む）、`Dockerfile`
- 依存リスト：`requirements.txt` `Pipfile` `pyproject.toml` `package.json` `go.mod` `Gemfile` `*.csproj` `*.vbproj` `*.fsproj` `packages.config` `pom.xml` `build.gradle(.kts)` `composer.json` `Cargo.toml` `Package.swift`

`.md` は意図的に対象外です。ドキュメントに `api.openai.com` が出てくるのは普通のことで、ノイズだらけになります。2 MB 超は飛ばします。
`.git`、`node_modules`、`__pycache__`、`.venv`、`venv`、`dist`、`build` には入りません。

3 つの手がかりの範囲は違います。鍵のパターンと AI ドメインは**言語に依存せず**、上のすべての種類が対象
（鍵は Anthropic、OpenAI の新旧、Google の 4 接頭辞のみ。ドメインは 7 つ）。
SDK の読み込みは `import` / `from` / `require` / `using` / `use` の 5 語を大文字小文字を区別せず見るので、Python、JS／TS、Go、Ruby、Java、Kotlin、Swift、Scala、Dart、C#／VB.NET、Rust、PHP をカバーします。
読み込み行と依存リストではベンダー名を部分一致で見るので、Rust の `async_openai`、Swift の `OpenAIKit`、C# の `Anthropic.SDK` も拾えます。他は単語単位です。
依存リストは常に低リスクとして報告します。

## このツールの出どころ

ある回の動画の付属ツールです。その回のテーマは、社内にいったい何件の登録されていない AI 呼び出しがあるのか、
そしてなぜ「禁止」の通達では止まらないのか——カメラが一台もない路地に「駐車禁止」の札を貼るようなものだから。

このツールは意図的に、リポジトリ 1 つを見て終わります。対象が 200 リポジトリで、定期実行が要り、監査に耐える記録が要り、
誤検知が二度と戻ってこないようにしたいなら、それは別の階層の問題です。そのために私たちは **ForgeHelm** を作りました。

まずはこの 1 つをスキャンしてください。冒頭の数字に戻って——まだ合っていると思いますか。
